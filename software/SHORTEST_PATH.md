# 最短路径演示与性能测试

本项目的演示程序 [shortest_path.c](shortest_path.c) 在 CPU 上生成固定的 24 节点带权图，再用 Dijkstra 算法计算指定起点到各节点的最短距离。图和算法含乘法、比较、分支及字节、半字、字访存；当前程序不使用除法和取余。SW4:0 在复位期间作为起点输入，24–31 会在 C 程序中减去 24；释放复位后，SW4:0 用于选择要查看的终点。

## 编译与仿真

在项目根目录执行以下命令，生成 ELF、BIN、反汇编，以及供仿真使用的机器码：

```powershell
.\software\build_shortest_path.ps1 -ToolBin 'D:\path\to\riscv-toolchain\bin'
```

打开 Vivado 工程 `RISCV_CPU.xpr`，以 `tb_cpu` 为仿真顶层运行 `Run All`。该 testbench 用 Floyd–Warshall 独立计算 24 个目的地的参考距离，并检查 CPU 结果。更完整的板上显示检查见 `tb_shortest_path.v`，老的指令检查见 `tb_all.v`。

| 输入起点 | 实际起点 | 距离总和 | 最大距离 | CPU 周期 | 50 MHz 用时 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 508 | 51 | 36812 | 0.73624 ms |
| 9 | 9 | 490 | 43 | 36752 | 0.73504 ms |
| 23 | 23 | 495 | 53 | 36803 | 0.73606 ms |
| 31 | 7 | 390 | 47 | 36994 | 0.73988 ms |

以上是当前 RTL 与机器码在仿真中的结果。优化分支预测或双发射后，可沿用同一机器码和相同输入比较周期数；板上实际用时还取决于最终通过时序的时钟频率。

## 板上演示

1. 设置 SW4:0 为起点（推荐 0），按住再松开复位按钮。
2. 等待 LED0 亮起，表示 C 程序完成。
3. 设置 SW4:0 为终点（0–23），通过 SW8:7 选择显示内容。

| SW8:7 | 数码管显示 |
| --- | --- |
| 00 | 复位时保存的起点 |
| 01 | 起点到当前终点的距离；终点 24–31 时熄灭 |
| 10 | 从释放复位到程序完成的用时，单位微秒 |
| 11 | 24 个终点最短距离之和 |

起点 0、终点 16 时，距离为 4，距离总和为 508，运行时间约 736 微秒。RTL 中 `elapsed_cycles` 保留精确 CPU 周期数；数码管时间为整数微秒。

## 内存布局与更新 bitstream

CPU 从字地址 0 读取起点；程序向字地址 1、2、3 写入可达数、总和、最大距离，向 4 写入摘要，向 5 写入完成标记 `0x600d`，向 16–39 写入全部 24 个距离。板上顶层捕获这些结果用于显示。

更新 C 程序后，先重新运行编译脚本，再把生成的 `software/shortest_path_riscvtest.txt` 复制到 `RISCV_CPU.srcs/sources_1/new/riscvtest.txt`，重新生成并下载 bitstream。只更新仿真镜像不会改变已经下载的程序。
